# Справочник метода API

Страница справочника описывает один метод REST API по правилам раздела [«Описание API»](../rules/api.md).

## Заготовка

````markdown
# <Действие в неопределенной форме, например «Создать бронирование»>

```http
<МЕТОД> /v1/<путь>
```

<Что делает метод. Какое право доступа нужно.>

## Запрос

### Заголовки

| Заголовок | Обязательный | Описание |
| --- | --- | --- |
| `Authorization` | Да | Токен доступа: `Bearer <токен>`. |

### Параметры пути

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `<имя>` | `<тип>` | <Да или Нет> | <Описание и ограничения.> |

### Тело запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `<имя>` | `<тип>` | <Да или Нет> | <Описание и ограничения.> |

## Ответ

<Статус успешного ответа.>

| Поле | Тип | Описание |
| --- | --- | --- |
| `<имя>` | `<тип>` | <Описание. Когда бывает null.> |

## Ошибки

| Статус | Код | Причина | Что сделать |
| --- | --- | --- | --- |
| <400> | `<code>` | <Причина> | <Действие разработчика> |

## Пример

```bash
curl -X <МЕТОД> "https://api.campusbook.example/v1/<путь>" \
  -H "Authorization: Bearer $CAMPUSBOOK_TOKEN"
```

```json
{ "<поле>": "<значение>" }
```
````

Разделы, которые не относятся к методу, удалите. Например, у метода без параметров пути нет раздела «Параметры пути».
