# Доступность текста

Раздел описывает, как писать документацию, которую поймут все читатели: те, кто пользуется экранным диктором или увеличением экрана, плохо различает цвета, читает на неродном языке. Префикс правил — `ACC`. Ориентир — рекомендации WCAG 2.2 уровня AA, которые относятся к тексту.

## ACC-01. Пишем простым языком {#acc-01}

**Рекомендуется.** Часть читателей КампусБук — иностранные студенты, для которых русский язык не родной. Текст для них должен переводиться онлайн-переводчиком без потери смысла.

- Используем распространенные слова и термины из [словаря](../glossary.md).
- Не используем идиомы, метафоры и игру слов: «с головой хватит», «как по маслу».
- Не пропускаем слова, которые понятны носителю языка из контекста.
- Отрицание ставим явно и одно на предложение: «Нельзя бронировать больше 3 аудиторий», а не «Не получится не превысить лимит».

<!-- stylecheck: off -->

| Неправильно | Правильно |
| --- | --- |
| Если аудитория не нашлась, не беда — попробуйте поиграть со временем. | Если свободных аудиторий нет, измените время начала. |

## ACC-02. Делаем заголовки опорой для навигации {#acc-02}

**Обязательно.** Пользователи экранного диктора перемещаются по странице от заголовка к заголовку. Поэтому:

- на странице один заголовок первого уровня, уровни идут без пропусков (см. [FMT-01](formatting.md#fmt-01));
- заголовок понятен без окружающего текста: «Отменить бронирование», а не «Как это сделать»;
- заголовки на одной странице не повторяются дословно.

## ACC-03. Пишем ссылки, понятные вне контекста {#acc-03}

**Обязательно.** Экранный диктор может зачитать список всех ссылок страницы подряд. Текст каждой ссылки должен объяснять, куда она ведет (см. [MD-05](markdown.md#md-05)).

- Не используем «здесь», «подробнее», «по ссылке».
- Две ссылки с одинаковым текстом ведут на одну и ту же страницу.
- Если ссылка ведет на файл, указываем формат и размер: «Правила пользования коворкингом (PDF, 240 КБ)».

## ACC-04. Описываем изображения альтернативным текстом {#acc-04}

**Обязательно.** У каждого изображения есть альтернативный текст (см. [FMT-08](formatting.md#fmt-08)). Он передает то, что читатель должен узнать из картинки, а не описывает ее внешний вид. Пустой альтернативный текст не пропустит `markdownlint` (правило MD045).

- Не начинаем со слов «Изображение», «Скриншот»: диктор и так сообщает, что это изображение.
- Длина — до 150 символов. Если нужно больше, описываем изображение в тексте рядом.
- Декоративные изображения (разделители, фоновые картинки) в документацию не добавляем: по FMT-08 изображение нужно, только когда без него не понять текст.
- Текст, который есть на картинке, дублируем в тексте страницы.

```markdown
![Окно подтверждения: аудитория 1405, 20 октября, 10:00–11:30, кнопка «Подтвердить»](img/confirm-booking.png)
```

## ACC-05. Не передаем смысл только цветом или положением {#acc-05}

**Обязательно.** Читатель может не различать цвета, видеть страницу в увеличенном масштабе или слушать ее. Указание «зеленая кнопка справа» для него бесполезно. Элемент называем по подписи (см. [FMT-04](formatting.md#fmt-04)), а цвет упоминаем только вместе с текстом.

<!-- stylecheck: off -->

| Неправильно | Правильно |
| --- | --- |
| Нажмите зеленую кнопку в правом верхнем углу. | Нажмите **Забронировать**. |
| Красным отмечены занятые аудитории. | Занятые аудитории отмечены словом «Занято» и красной меткой. |

<!-- stylecheck: on -->

## ACC-06. Делаем таблицы читаемыми для диктора {#acc-06}

**Обязательно.** Диктор читает таблицу по ячейкам и называет заголовок столбца для каждой ячейки.

- У таблицы всегда есть строка заголовков, заголовки не пустые (см. [FMT-06](formatting.md#fmt-06)).
- Не объединяем ячейки и не оставляем строки-разделители.
- Если в таблице больше 5 столбцов, разбиваем ее на несколько или заменяем списком.

## ACC-07. Не заменяем слова символами {#acc-07}

**Обязательно.** Диктор читает символы по-разному или пропускает их. Пишем «и», «или», «примерно», «от ... до», а не «&», «/», «~», «≈». Исключение — стрелка «→» в пути по меню (см. [FMT-04](formatting.md#fmt-04)): ее диктор зачитывает как «стрелка вправо», и путь остается понятным.

## ACC-08. Проверяем страницу вручную перед публикацией {#acc-08}

**Рекомендуется.** Автоматические проверки не находят большинство проблем доступности. Новую или сильно измененную страницу автор проверяет сам:

1. Откройте страницу локально командой `mkdocs serve`.
2. Включите экранный диктор: VoiceOver в macOS (`Cmd + F5`) или NVDA в Windows.
3. Пройдите по заголовкам страницы. Проверьте, что по ним понятна структура.
4. Откройте список ссылок. Проверьте, что каждая ссылка понятна без окружающего текста.
5. Увеличьте масштаб страницы до 200 %. Проверьте, что текст не обрезается и не нужна горизонтальная прокрутка.
6. Пройдите страницу клавишей `Tab`. Проверьте, что фокус виден на каждой ссылке и кнопке.

Результат проверки укажите в описании Pull Request.
