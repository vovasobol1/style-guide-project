# Markdown

Раздел описывает разметку исходных файлов документации. Префикс правил — `MD`. Большую часть правил проверяет `markdownlint`, настройки лежат в файле `.markdownlint-cli2.jsonc`.

## MD-01. Называем файлы латиницей {#md-01}

**Обязательно.** Одна страница — один файл. Имя файла пишем латиницей в нижнем регистре, слова разделяем дефисом: `book-room.md`, `create-booking.md`. Имя отражает содержание страницы.

## MD-02. Начинаем файл с заголовка первого уровня {#md-02}

**Обязательно.** Первая строка файла — заголовок `#`. Заголовки размечаем только символами `#`, подчеркивание `===` и `---` не используем. Вокруг заголовка оставляем пустые строки.

Чтобы на правило можно было сослаться, заголовок правила получает явный якорь:

```markdown
## TON-01. Обращаемся к читателю на «вы» {#ton-01}
```

## MD-03. Размечаем списки единообразно {#md-03}

**Обязательно.**

- Маркер маркированного списка — дефис `-`.
- Нумерованный список нумеруем по порядку: `1.`, `2.`, `3.`.
- Вложенный список и продолжение пункта сдвигаем на 4 пробела. Меньший отступ MkDocs не распознает.

## MD-04. Указываем язык блока кода {#md-04}

**Обязательно.** Блоки кода оформляем тремя обратными апострофами и указываем язык: `bash`, `json`, `http`, `yaml`, `markdown`, `text`. Отступ в 4 пробела для кода не используем.

````markdown
```bash
mkdocs serve
```
````

## MD-05. Пишем понятный текст ссылки {#md-05}

**Обязательно.** Текст ссылки описывает страницу, на которую она ведет. Не пишем «здесь», «тут», «по ссылке». Ссылки на страницы руководства указываем относительным путем к файлу `.md`, чтобы сборка проверила их.

<!-- stylecheck: off -->

| Неправильно | Правильно |
| --- | --- |
| Шаблон можно найти [здесь](../doc-templates/index.md). | Возьмите [шаблон статьи справки](../doc-templates/help-article.md). |

<!-- stylecheck: on -->

## MD-06. Не переносим строки внутри абзаца {#md-06}

**Рекомендуется.** Абзац пишем одной строкой. Так в истории изменений видно, какое именно предложение поменялось, а редактор сам переносит длинные строки. Пробелы в конце строк не оставляем.

## MD-07. Не используем HTML {#md-07}

**Обязательно.** Все оформление делаем средствами Markdown. Исключение — комментарии-маркеры для `stylecheck`, которые отключают проверку на участке с примерами нарушений:

```markdown

<!-- stylecheck: off -->

| Неправильно | Правильно |
| --- | --- |
| Пример с нарушением | Исправленный пример |

<!-- stylecheck: on -->

```

Маркеры ставим только вокруг примеров «как не надо», а не вокруг основного текста.

## MD-08. Проверяем файл перед Pull Request {#md-08}

**Обязательно.** Перед отправкой изменений запускаем проверки:

```bash
npm run lint
mkdocs build --strict
```

Те же проверки выполняет CI в каждом Pull Request.
