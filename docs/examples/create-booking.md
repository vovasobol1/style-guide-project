# Создать бронирование

```http
POST /v1/bookings
```

Создает бронирование помещения на указанный интервал от имени пользователя, которому выдан токен. Метод доступен интеграциям с правом `bookings:write`.

## Запрос

### Заголовки

| Заголовок | Обязательный | Описание |
| --- | --- | --- |
| `Authorization` | Да | Токен доступа: `Bearer <токен>`. |
| `Content-Type` | Да | Только `application/json`. |
| `Idempotency-Key` | Нет | Уникальная строка до 64 символов. Повтор запроса с тем же ключом в течение 24 часов вернет уже созданное бронирование, а не создаст второе. |

### Тело запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `room_id` | `string` | Да | Идентификатор помещения из ответа метода `GET /v1/rooms`. |
| `start_at` | `string (date-time)` | Да | Начало интервала по ISO 8601 с часовым поясом. Минуты кратны 15. |
| `end_at` | `string (date-time)` | Да | Окончание интервала. Длительность — от 30 минут до 4 часов. |
| `attendees` | `integer` | Да | Число участников, от 1 до вместимости помещения. |
| `purpose` | `string` | Нет | Цель бронирования, до 200 символов. Видна администратору корпуса. |

## Ответ

Статус `201 Created`.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string` | Идентификатор бронирования. |
| `status` | `string` | Всегда `confirmed` для нового бронирования. |
| `room_id` | `string` | Идентификатор помещения. |
| `start_at` | `string (date-time)` | Начало интервала. |
| `end_at` | `string (date-time)` | Окончание интервала. |
| `check_in_deadline` | `string (date-time)` | Время, до которого нужно отметиться в помещении. После него бронирование отменится. |
| `purpose` | `string` | Цель бронирования. Если поле не передали в запросе, значение `null`. |

## Ошибки

| Статус | Код | Причина | Что сделать |
| --- | --- | --- | --- |
| 400 | `invalid_interval` | Окончание раньше начала, минуты не кратны 15 или длительность вне диапазона | Проверьте `start_at` и `end_at` по ограничениям из таблицы тела запроса. |
| 401 | `unauthorized` | Токен не передан или истек | Получите новый токен и повторите запрос. |
| 403 | `forbidden` | У токена нет права `bookings:write` | Запросите право у администратора КампусБук. |
| 404 | `room_not_found` | Помещение с таким `room_id` не существует | Получите актуальный список помещений методом `GET /v1/rooms`. |
| 409 | `room_unavailable` | Помещение занято на часть интервала | Выберите другой интервал методом `GET /v1/rooms/{room_id}/availability`. |
| 409 | `booking_limit_reached` | У пользователя уже 3 активных бронирования | Предложите пользователю отменить одно из бронирований. |
| 422 | `capacity_exceeded` | Значение `attendees` больше вместимости помещения | Выберите помещение с большей вместимостью. |
| 429 | `too_many_requests` | Больше 60 запросов в минуту с одного токена | Повторите запрос через число секунд из заголовка `Retry-After`. |

**Важно.** Если ответ не пришел из-за обрыва соединения, бронирование могло создаться. Повторяйте запрос с тем же `Idempotency-Key`, иначе у пользователя появится второе бронирование на тот же интервал.

## Пример

Запрос бронирует аудиторию на полтора часа для четырех участников:

```bash
curl -X POST "https://api.campusbook.example/v1/bookings" \
  -H "Authorization: Bearer $CAMPUSBOOK_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 5f0c2b9e-team-meeting" \
  -d '{
    "room_id": "kronv-49-1405",
    "start_at": "2026-10-20T10:00:00+03:00",
    "end_at": "2026-10-20T11:30:00+03:00",
    "attendees": 4,
    "purpose": "Встреча проектной команды"
  }'
```

Ответ:

```json
{
  "id": "bk_8Hq2LmZx",
  "status": "confirmed",
  "room_id": "kronv-49-1405",
  "start_at": "2026-10-20T10:00:00+03:00",
  "end_at": "2026-10-20T11:30:00+03:00",
  "check_in_deadline": "2026-10-20T10:15:00+03:00",
  "purpose": "Встреча проектной команды"
}
```
