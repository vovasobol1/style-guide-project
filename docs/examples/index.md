# Проверка руководства

Чтобы проверить руководство, мы написали по нему два документа разных типов и оценили, помогают ли правила и где их не хватает.

| Документ | Тип | Шаблон |
| --- | --- | --- |
| [Забронировать аудиторию](book-room.md) | Статья справки для пользователей | [Статья справки](../doc-templates/help-article.md) |
| [Создать бронирование](create-booking.md) | Справочник метода REST API | [Справочник метода API](../doc-templates/api-method.md) |

## Как проверяли

1. Написали документы по шаблонам, сверяясь с разделами правил.
2. Прошли по каждому документу со списком правил и отметили, выполнено ли правило.
3. Запустили `npm run lint` (markdownlint и stylecheck) и `mkdocs build --strict`.
4. Каждую трудность при написании записали как замечание к руководству.

## Что нашли и исправили

| Проблема | Как исправили |
| --- | --- |
| `stylecheck` считал нарушением упоминание слова в описании правила: TON-05 нарушало само себя, когда перечисляло слова «просто» и «легко» | Текст в «елочках» считается цитатой и не проверяется. Это описано в справке скрипта |
| В справке нужно было привести текст ошибки из интерфейса, а правило FMT-04 описывало только кнопки и поля | В FMT-04 добавили правило для сообщений интерфейса: в «елочках», точно как на экране |
| Нежелательное слово «данный» совпадало с существительным «данные» | Шаблон в `scripts/stop_words.txt` ограничили формами прилагательного. Проверили на тестовом тексте, что «данные» не отмечаются |

## Оценка руководства

**Что работает.** Шаблоны задают структуру, и оба документа получились полными без дополнительных вопросов. Правила API-03 и API-08 заставили описать `null` и повтор запроса — без них эти сведения часто пропускают. Идентификаторы правил позволяют коротко ссылаться на них в ревью.

**Что проверяется автоматически.** `markdownlint` проверяет разметку по разделу «Markdown», `stylecheck` — правила ORF-01–ORF-04, TON-01, TON-04, TON-05 и TRM-03. Остальные правила (тон, структура, порядок шагов) проверяет только человек на ревью.

**Чего не хватает.** В руководстве нет правил доступности текста: альтернативного текста изображений, структуры заголовков для экранного диктора, текста для читателей, у которых русский язык не родной. Это следующий раздел руководства.
