# Руководство по стилю документации КампусБук

КампусБук — сервис бронирования аудиторий, переговорных и мест в коворкингах кампуса ИТМО. Руководство описывает, как писать и оформлять документацию сервиса: справку для пользователей, справочник REST API и списки изменений.

Руководство нужно, чтобы:

- документы, написанные разными авторами, читались как написанные одним человеком;
- читатель быстро находил ответ и не спотыкался о разные названия одного и того же;
- ревью сводилось к ссылкам на правила, а не к спорам о вкусе;
- новый автор мог начать писать по шаблону в первый же день.

## Как устроены правила

Каждое правило имеет идентификатор, уровень и пример.

- **Идентификатор** состоит из префикса раздела и номера: `TON-03`, `API-05`. На правило можно сослаться в ревью или коммите.
- **Обязательно** — правило проверяется на ревью, Pull Request с нарушением не принимается.
- **Рекомендуется** — от правила можно отступить, если причина описана в Pull Request.

Если правило проверяется автоматически, в его описании указан инструмент: `markdownlint` или `stylecheck`.

## Как пользоваться руководством

1. Перед новым документом откройте [шаблон](doc-templates/index.md) нужного типа.
2. Пишите текст, сверяясь с разделами правил.
3. Запустите проверки: `npm run lint` и `mkdocs build --strict`.
4. Откройте Pull Request и укажите в описании, по каким правилам есть отступления.

Как предложить изменение в само руководство, описано в файле `CONTRIBUTING.md` в корне репозитория.
