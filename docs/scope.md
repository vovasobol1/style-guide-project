# Область применения

## Объект руководства

Руководство распространяется на внешнюю и внутреннюю документацию сервиса КампусБук. Сервис состоит из веб-приложения для студентов и сотрудников и REST API для интеграций: бота расписания, панели администратора корпуса, табло у аудиторий.

## Виды документов

| Документ | Читатель | Где публикуется | Шаблон |
| --- | --- | --- | --- |
| Статья справки | Студент, преподаватель, сотрудник | Раздел «Помощь» в веб-приложении | [Статья справки](doc-templates/help-article.md) |
| Справочник метода API | Разработчик интеграции | Портал документации API | [Справочник метода API](doc-templates/api-method.md) |
| Список изменений | Все читатели | Портал документации и рассылка | [Список изменений](doc-templates/release-notes.md) |
| README репозитория | Разработчик команды | Репозиторий сервиса | — |

Руководство не регулирует тексты интерфейса (подписи кнопок, всплывающие подсказки) и стиль программного кода. Для них в команде есть отдельные договоренности.

## Читатели

**Пользователи сервиса** — студенты, преподаватели и сотрудники ИТМО. Открывают справку, когда не получается выполнить действие. Читают с телефона между парами, поэтому им нужен короткий ответ без вступлений. Часть студентов — иностранцы, для которых русский язык не родной.

**Разработчики интеграций** — знают HTTP и JSON, но не знают внутреннего устройства сервиса. Им нужны точные типы, ограничения и примеры, которые можно скопировать и выполнить.

**Команда сервиса** — разработчики, тестировщики, аналитик. Пишут и проверяют документацию, используют ее при онбординге.

## Приоритет источников

Если правила противоречат друг другу, действует источник, который выше в списке:

1. Это руководство и [словарь терминов](glossary.md).
2. Договоренность, зафиксированная в Pull Request к этому руководству.
3. Справочник по русскому языку: орфографический словарь РАН, справочник А. Э. Мильчина по оформлению текста.
4. Google Developer Documentation Style Guide — для вопросов, которые не описаны в руководстве.

Если случай не описан ни в одном источнике, автор принимает решение сам и предлагает новое правило через Pull Request.
